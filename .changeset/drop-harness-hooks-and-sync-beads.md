Agent sessions no longer pay for work they did not ask for. The three Oh My Pi extensions are gone: nothing formats after every edit, runs `mise run check` before every stop, or injects `bd prime` into the first turn. The `pre-commit` hook still formats staged files, the agent still runs `mise run check` before claiming work is done, and the `pre-push` hook no longer runs the gate. CI runs it on every push, and agents wait for CI to pass before marking a pull request ready or merging it.

Beads now stays current across machines. `mise run status` syncs this machine's Beads replica with `refs/dolt/data` on the project's own repository, then shows the sync outcome, ready work, the items in progress and who holds them, and the project's memories; `--json` adds a `beads` object. `git push` and `git pull` sync through hk, `mise run beads:sync` syncs on demand, and `mise run beads:claim -- <id>` claims an item as `<user>@<short host>` and reports whether the claim survived the sync (`claimed`, `claimed-unpublished`, `held`, or `lost`). No sync creates a Git branch, so GitHub shows no "recently pushed" banner. The `tracking-work` skill explains replicas, claims, and how to settle a sync conflict. `mise run setup` restores an existing project's replica with `bd bootstrap` instead of creating an unrelated database. GitHub Issues and Projects hold the owner's planning; Beads holds the work agents discover and the project's memory.

What adopters have to do: delete `.omp/extensions/` and `tools/format-after-edit.test.ts`; copy `tools/beads.ts`, `tools/beads-report.ts`, `tools/fake-bd.ts`, `tools/beads.test.ts`, and `.agents/skills/tracking-work/recovering-a-sync.md`; and merge the changes to `mise.toml` (the `DOLT_REMOTE_INFO_BRANCH` entry, the `beads:sync` and `beads:claim` tasks, and `setup`), `hk.pkl` (the `pre-push` and `post-merge` steps, and no `pre-push` check), `.beads/config.yaml` (`dolt.auto-push: false`), `tools/status.ts`, `tools/status.collection.test.ts`, `tsconfig.json`, `AGENTS.md`, `PROCESS.md`, `README.md`, the `tracking-work`, `writing-a-proposal`, `implementing-a-proposal`, `reviewing-an-implementation`, and `completing-a-feature` skills, the enforcement hierarchy, `.github/workflows/ci.yml`, and the `adapting-your-harness`, `getting-started`, `record-validation`, and `running-a-feature` guides. A project that set `dolt.auto-push: true` turns it off, and one whose repository has a `__dolt_remote_info__` branch deletes it once. Then run `mise run setup` on every machine. Claims made before this change hold a Git user name; move your own to `<user>@<short host>` as the `tracking-work` skill describes.
