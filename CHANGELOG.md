# workbench

## 0.1.0

### Minor Changes

- [#11](https://github.com/markmals/workbench/pull/11) [`d380558`](https://github.com/markmals/workbench/commit/d380558dd7e2d187a0bc5a11cc3c84f0a171a54c) Thanks [@markmals](https://github.com/markmals)! - Agent sessions no longer pay for work they did not ask for. The three Oh My Pi extensions are gone: nothing formats after every edit, runs `mise run check` before every stop, or injects `bd prime` into the first turn. The `pre-commit` hook still formats staged files, the agent still runs `mise run check` before claiming work is done, and the `pre-push` hook no longer runs the gate. CI runs it on every push, and agents wait for CI to pass before marking a pull request ready or merging it.

    Beads now stays current across machines. `mise run status` syncs this machine's Beads replica with `refs/dolt/data` on the project's own repository, then shows the sync outcome, ready work, the items in progress and who holds them, and the project's memories; `--json` adds a `beads` object. `git push`, `git pull`, and rebases sync through hk, and `mise run beads:sync` syncs on demand. `mise run beads:claim -- <id>` claims an item as `<user>@<short host>` and reports whether the claim survived the sync (`claimed`, `claimed-unpublished`, `held`, or `lost`); `mise run beads:close -- <id> "<reason>"` closes it as the same claimant and syncs. No sync creates a Git branch, so GitHub shows no "recently pushed" banner, and no sync runs against a Beads remote that is not the project's own `origin`. The `tracking-work` skill explains replicas, claims, and how to settle a sync conflict. `mise run setup` restores an existing project's replica with `bd bootstrap` instead of creating an unrelated database. GitHub Issues and Projects hold the owner's planning; Beads holds the work agents discover and the project's memory.

    What adopters have to do: delete `.omp/extensions/` and `tools/format-after-edit.test.ts`; copy `tools/bd.ts`, `tools/beads.ts`, `tools/beads-claims.ts`, `tools/beads-cli.ts`, `tools/beads-remote.ts`, `tools/beads-report.ts`, `tools/fake-bd.ts`, `tools/beads.test.ts`, and `.agents/skills/tracking-work/recovering-a-sync.md`; and merge the changes to `mise.toml` (the `DOLT_REMOTE_INFO_BRANCH` entry, the `beads:sync`, `beads:claim`, and `beads:close` tasks, and `setup`), `hk.pkl` (the `pre-push`, `post-merge`, and `post-rewrite` steps, and no `pre-push` check), `.beads/config.yaml` (`dolt.auto-push: false`), `tools/status.ts`, `tools/status.collection.test.ts`, `tsconfig.json`, `AGENTS.md`, `PROCESS.md`, `README.md`, the `tracking-work`, `writing-a-proposal`, `implementing-a-proposal`, `reviewing-an-implementation`, and `completing-a-feature` skills, the enforcement hierarchy, `.github/workflows/ci.yml`, and the `adapting-your-harness`, `getting-started`, `record-validation`, and `running-a-feature` guides. A project whose `.beads/` came from the Workbench template replaces it as the getting-started guide describes; until then, its syncs fail rather than reach Workbench's repository. A project that set `dolt.auto-push: true` turns it off, and one whose repository has a `__dolt_remote_info__` branch deletes it once. Then run `mise run setup` on every machine. Claims made before this change hold a Git user name; move your own to `<user>@<short host>` as the `tracking-work` skill describes.

- [#9](https://github.com/markmals/workbench/pull/9) [`a9826cb`](https://github.com/markmals/workbench/commit/a9826cbcf4a363fdcc678c1a470fa4287b5ec00b) Thanks [@markmals](https://github.com/markmals)! - Maintain current requirements in API contracts, reference documentation, or Gherkin as appropriate to each surface. Proposals now explain changes to those sources. Workbench includes reusable optional Gherkin authoring guidance, examples, and a feature template without requiring a new runner or specification registry.

    Policies and decisions can be revised in place or retired. When adopting this version, remove their `supersedes` metadata and consolidate any still-applicable requirements before deleting old records. `established-by` is optional historical provenance. Replace guide `describes` metadata with ordinary links to current sources, and update the validator, record templates, process skills, and guides together. Historical proposal relationships and native test suites remain supported.

- [#8](https://github.com/markmals/workbench/pull/8) [`3a6311e`](https://github.com/markmals/workbench/commit/3a6311ee801b12a014c314d8121c537570f58973) Thanks [@markmals](https://github.com/markmals)! - Proposals now say what a feature does and leave its look and feel — layout, sizes, spacing, type, color, motion, which control presents a choice, how it is operated, and wording — to the human on the running UI. Look-and-feel feedback during human review is applied while the proposal stays `active-review`, with no proposal edit, status change, readiness report, or second adversarial review. Polishing an interface between proposals needs no proposal question; the new `polishing-a-ui` skill describes the loop and stops when a request would change what the feature does.

    What adopters have to do: copy `.agents/skills/polishing-a-ui/`, and merge the changes to `AGENTS.md` ("Does this change need a proposal?" and "Stay inside the proposal"), `PROCESS.md` (the new Look and feel section, the self-check, and Human Review), `README.md`, the `writing-a-proposal`, `implementing-a-proposal`, `reviewing-an-implementation`, and `adversarial-review` skills, the proposal and pull-request templates, the status messages in `tools/status.ts`, and the `running-a-feature` and `writing-a-good-proposal` guides. Existing proposals need no edits; look-and-feel details already written into one stand as decided at the time and may be refined through polish without revising it.

- [`6847049`](https://github.com/markmals/workbench/commit/68470498ff0e9f644afd603db2391c4e0f24646d) Thanks [@markmals](https://github.com/markmals)! - Replace the Vite+ toolchain with the platform-neutral tooling layer the project templates share: mise owns every pinned tool and every task, hk owns every git hook, Fnox owns secrets, Beads owns the work graph, Changesets owns the changelog, and Worktrunk owns worktrees.

    What adopters have to do: install mise, then run `mise install` and `mise run setup` instead of `vp install`. In an existing checkout, first run `git config --unset core.hooksPath`: hk registers its hooks through git's `hook.<name>.command` config, and a leftover `core.hooksPath` from `vp config` keeps the old Vite+ hooks running beside them, so commits fail. Every command changes name — `mise run check` is the gate, `mise run status` reports the phase, `mise run fmt` formats. Formatting, lint and type checking now come from `.oxfmtrc.jsonc`, `.oxlintrc.jsonc` and `tsrs` rather than `vite.config.ts`, which is gone along with `.agents/hooks/`; the `commit-msg` hook reads its scopes from the new `.agents/commit-scopes`. Deferred defects go to Beads instead of GitHub issues, and the `tracking-defects` skill is now `tracking-work`. Every pull request carries a changeset.
